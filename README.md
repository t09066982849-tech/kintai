# 勤怠管理システム(kintai)

株式会社伊豆倉組の勤怠管理システム。タッチオンタイム・タイムツリー・シャチハタクラウドの3つを、このシステム1つに統合するのが目的。9/1リリース目標。Asanaプロジェクト:https://app.asana.com/1/1216844938289140/project/1217137088641946

## 構成

- **フロント**:素のHTML/CSS/JavaScript(フレームワークなし)。GitHubにpush→Vercelが自動デプロイ。
- **バックエンド**:Supabase(PostgreSQL + Auth + Edge Functions)。サーバー(Railway等)は使わない方針。
- **メール送信**:Resend(送信元 `kintai-noreply@izukura.co.jp`)。Edge Functions経由でのみ使用(ブラウザに鍵を置かないため)。
- **祝日データ**:`holidays-jp.github.io`の無料APIから取得。
- **本番URL**:`kintai-ten-ruby.vercel.app`
- **GitHubリポジトリ**:`t09066982849-tech/kintai`

## データベース(Supabase)テーブル

- `employees`:従業員マスタ。`is_admin`、`department`(civil/accounting)、`role`(president/director/manager_civil/manager_accounting/null)、`travel_rate_group_id`、`paid_leave_balance`(残り有給日数、現在全員0で初期化済み・実データ反映待ち)
- `sites`:現場マスタ。`work_start`/`work_end`(所定時間、事務所は8:30-17:30、その他は7:00-17:00がデフォルト。残業・補正計算に使用)
- `time_records`:打刻記録。実時刻のみ保存(計算型)。出退勤GPS付き。**実時刻は画面・Excel・管理者にも一切表示しない**(証跡として裏に保持するのみ)。表示・出力は必ず`common.js`の`computeDayMetrics`で補正した値を使う
- `correction_requests`:既存の打刻記録の時刻+現場を直す申請。管理者が承認/却下。早出・残業(所定時間超過分)は`app.js`側で自動的に所定時刻に丸められる(遅刻・早上がりは自由入力可)
- `missing_record_requests`:打刻記録が丸ごと存在しない日の追加申請(出勤忘れ・退勤忘れの当日も含む)。`requested_clock_in`必須、`requested_clock_out`は任意。承認されると新規`time_records`行が作られる(退勤未入力ならNULLのまま、後で通常の退勤ボタンが使える)
- `schedules`:スケジュール。`type`は event/paid_leave/business_trip。複数日対応(`end_date`)。全員閲覧可
- `schedule_members`:スケジュールの参加メンバー(多対多)
- `leave_requests`:有給・出張申請。3段階承認の状態を保持。出張は`zone`/`daily_allowance`/`hotel_fee`/`total_amount`も持つ。有給は全承認完了時に`employees.paid_leave_balance`から自動減算
- `travel_rate_groups` / `travel_rates`:旅費規程(グループ単位で道内/道外の日当・宿泊費)
- `holidays`:全国の祝日マスタ(`sync-holidays`で自動取得)。**経理部の休日判定にのみ使用**。土木部は使わない(下記参照)
- `company_holidays`:会社独自の休業期間(GW・お盆・年末年始など、`start_date`〜`end_date`)。**土木部の休日判定に使用**。現在登録済み:GW(5/3-5/5)、お盆(8/13-8/15)、年末年始(12/29-1/4)。年ごとに手動で追加・更新が必要

### 部署によって休日の考え方が違う(重要)

土木部は現場都合で祝日(飛び石)でも稼働することが多いが、GW・お盆・正月はまとまって休業する。経理部は祝日を含めて通常のカレンダー通り休む。そのため打刻漏れチェック(`check-missing-punches`系)は部署ごとに判定ロジックを分けている。

- 経理部(`department = 'accounting'`):土日 + `holidays`テーブルの祝日を除外
- 土木部(それ以外):土日 + `company_holidays`の期間のみ除外(祝日そのものは通常営業として扱う)

スケジュールのカレンダー表示(`schedule.js`)は全社共通で`holidays`を赤字表示に使っているが、これは表示上の参考情報であり、打刻漏れ判定とは連動していない。

## Supabase Edge Functions

- `check-missing-punches`:毎日12時実行(cron設定済み)。「前日」ではなく、部署ごとの休日ルールに従って遡った直近の稼働日分の打刻漏れを検知しメール通知(2026-08-12修正:部署別の休日判定に対応)。**現在RESTRICT_TO_SHIMAKI=trueで嶋木さんのみ対象**(全員分の動作確認が済んだらfalseに戻す)
- `check-missing-punches-biweekly`:毎月1日・16日12時実行(cron設定済み)。直近15日分をまとめて棚卸し。部署別の休日ルールに対応済み(2026-08-12)。**まだ絞り込み(RESTRICT_TO_SHIMAKI相当)が入っていないため、実行すると28人全員分がTEST_MODE宛先(嶋木さん)に届く**。8/16の本番実行結果を見てから絞り込み追加を判断する
- `notify-leave-approval`:leave.jsから都度呼び出し。申請時→部長、各承認時→次の承認者、全承認完了時→申請者本人にメール
- `sync-holidays`:祝日データ取得(手動実行。今後は年1回の自動実行cronを検討)

**3つの通知系Edge FunctionsはすべてTEST_MODE=trueのまま。本番切り替え時は`TEST_MODE = false`に変更し、`RESTRICT_TO_SHIMAKI`も外すこと。**

## 開発ルール

- **合言葉方式**:コード変更は必ず内容を先に説明し、ユーザーが「やっちゃいな」と言うまで実行しない(GitHubコミット・Supabase操作とも)。「進めよう」等の曖昧な同意では実行しないこと。これまで複数回、この合言葉ルールを守らず実装まで進めてしまった事例があった(2026-08-06、2026-08-11)。「次にやることを説明した直後、その説明自体を許可と混同する」のが典型的な失敗パターンなので、コードの説明をした回では絶対にツールを呼ばず、必ず一度返答を止めて次のユーザー発言を待つこと。
- GitHubへの直接コミットは、Claudeが専用のFine-grained PAT(このリポジトリのみ、Contents:Read and write)を使って行っている。トークンは別途ユーザーから都度受け取る運用。
- Supabase(SQL実行、Edge Functions編集、Secrets登録)はユーザーが手動で行う(直接接続は未設定)。
- 複数アカウントでの同時ログインテストは、タブではなく別ブラウザ/シークレットウィンドウを使うこと(セッションが競合するため)。

## 修正履歴(重要なバグ)

- **2026-08-10**:`check-missing-punches`で2つのバグを発見・修正。①「前日」を単純計算していたため、月曜実行時に日曜(対象外の日)を見てしまい、金曜分の打刻漏れを見逃していた→土日・祝日を遡って直近の平日を探す方式に修正。②スケジュール除外判定で、`end_date`がnull(単日の予定)の場合を「無期限」と誤解釈し、1日だけの有給がそれ以降ずっと除外対象になっていた→`end_date`がnullの場合は`date`と同日のみ対象とするよう修正。`check-missing-punches-biweekly`は元々正しい書き方だったため同バグはなし。
- **2026-08-11**:`common.js`の`computeDayMetrics`で、`sites.work_start/work_end`(DB上はtime型で秒付き文字列`08:30:00`)を分付き前提(`08:30`)で日時組み立てしていたため、`Invalid Date`(NaN)が発生し残業時間・補正表示が壊れていた。→ `.slice(0, 5)`で先頭5文字に切り詰めてから使うよう修正。
- **2026-08-12**:祝日一律除外の設計不備が判明。当初「祝日は全員休み」という前提で`check-missing-punches`系を実装したが、実際は土木部が祝日(飛び石)でも稼働することがあり、逆に経理部は祝日通り休む。単純な「連休なら休み」ルールも実態(月曜祝日でも稼働日がある)に合わず断念。→ 部署ごとに休日判定ロジックを分岐(経理部=`holidays`、土木部=`company_holidays`のみ)する方式に変更。
